Version 2026.2.2

New Features

  • Requisite cycle detection — states are now checked for circular dependencies between require, watch, and other requisites, correctly distinguishing states with the same ID that live in different modules.
  • Duplicate state ID detection — duplicate state IDs are flagged both within a single SLS file and across the whole project, with Jinja-generated IDs and IDs used only via extend correctly excluded.
  • Argument type validation — state function arguments are checked against their expected type (string, list, mapping, boolean, integer, number), catching type mistakes before they reach Salt.
  • State declaration validation — flags malformed state declarations, such as an invalid number of functions or duplicate modules within a single state.
  • listen_in requisite — full completion, structural validation, and Ctrl+Q quick documentation support.
  • onfail_all requisite — completion, structural validation, and quick documentation explaining its AND-logic semantics.
  • *_any requisites — completion and structural validation for require_any, watch_any, onchanges_any, and onfail_any.
  • Bare state ID requisites — bare state IDs used in require, require_any, and related requisites are now recognized, validated, and offered in completion.
  • Wildcard requisites — wildcard patterns (*, ?, [ ]) in pkg, file, and service requisites are recognized, avoiding false "unresolved ID" warnings.
  • Stricter requisite value checks — require_any, require_in, and other alternative/reverse requisites now report an error when given a scalar value instead of a list.
  • Expanded global arguments — completion and validation for all global state arguments, including umask, parallel, reload_modules, reload_pillar, reload_grains, fire_event, cmd_opts_exclude, and saltenv, plus refined checks for onlyif/unless, retry, and order: first.
  • Smarter Jinja handling — includes, requisites, and salt:// references no longer report false warnings for Jinja-templated content.
  • Crash reporting — the plugin can now submit anonymous error reports directly to the developers, helping fix issues faster.

Bug Fixes

  • Fixed the IDE freezing for up to 17 seconds when metadata settings were loaded from a slow or unresponsive remote server; the status is now refreshed asynchronously.

Version 2026.2.1

New Features

  • Top file support — full validation and code completion for top.sls files: environment structure validation, matcher key diagnostics, and SLS path resolution.
  • Matcher validation — 13 matcher types are now validated in top.sls: glob, pcre, grain, grain_pcre, pillar, pillar_exact, compound, ipcidr, list, nodegroup, range, data, and explicit match: <type> declarations.
  • Top file completion — code completion for environments, matcher types, and SLS entry paths (dot-notation) based on configured file and pillar roots.
  • Quick Documentation for top files — Ctrl+Q now provides context-sensitive documentation for environments and matcher keys in top.sls.
  • SLS path validation — dot-notation SLS paths are validated against the project file tree; Jinja expressions in paths are recognized and skipped.
  • Pillar root support — completions and validation in pillar top.sls files now resolve paths against configured pillar roots.
  • What's New notifications — in-IDE notifications about plugin updates with an embedded "What's New" tab.
  • File type conflict handling — improved detection and resolution of .sls file type conflicts with other plugins.
  • IntelliJ Platform 2026.2 support — compatible with build 262.*.

Bug Fixes

  • Fixed SLS completion for quoted YAML entries.
  • Fixed init.sls files being shown as raw paths instead of parent state names in completion results.
  • Top files (top.sls) are no longer suggested as SLS entries in completions.

Version 2026.2.0

New Features

  • Enhanced Jinja highlighting in Salt files — YAML syntax highlighting now works correctly across embedded Jinja fragments, preserving proper colors and code insight for both YAML and Jinja regions.
  • Automatic Jinja2 support for .sls files — the .sls extension is now automatically registered for Jinja2 support when a project is opened, eliminating the need for manual configuration.
  • IntelliJ Platform 2026.2 support — compatible with build 262.*.

Improvements

  • Improved error reporting with better crash diagnostics.
